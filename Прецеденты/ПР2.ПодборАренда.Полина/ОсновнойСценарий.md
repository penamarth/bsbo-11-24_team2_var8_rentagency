# ПР2. Подбор жилья и согласование заявки

**Цель** — подобрать доступное жильё, подать заявку на аренду и получить по ней решение владельца.

**Основной исполнитель** — арендатор. **Участники** — владелец жилья, который принимает решение по заявке на свой объект. Агент в прецеденте не участвует.

**Предусловия** — арендатор вошёл в систему. В каталоге есть хотя бы один доступный объект. Владелец вошёл в систему, когда рассматривает заявку.

## Основной сценарий

1. Арендатор открывает каталог. Система показывает первую страницу: 10 самых популярных доступных объектов в виде карточек (адрес, площадь, число комнат, месячная плата, фото).
2. Арендатор задаёт критерии поиска: город, диапазон цены, число комнат. Любой критерий можно не указывать.
3. Система проверяет критерии и отбирает только доступные объекты. Она показывает страницу из 10 карточек. Пустая выдача считается обычным результатом поиска.
4. Арендатор открывает карточку выбранного объекта.
5. Система проверяет, что объект доступен, и показывает карточку с фотографиями. В карточке есть действия «Записаться на просмотр» и «Подать заявку».
6. Арендатор выбирает «Подать заявку» сразу из карточки (просмотр необязателен) и вводит желаемые даты начала и окончания аренды.
7. Система проверяет роль арендатора, доступность объекта, отсутствие у арендатора другой активной заявки на этот объект и корректность дат. В одной неделимой операции она создаёт заявку «Подана» с месячной платой объекта и показывает её арендатору.
8. Владелец открывает заявки по своему объекту и изучает заявку арендатора.
9. Владелец одобряет заявку.
10. Система проверяет, что пользователь является владельцем этого объекта, заявка по-прежнему «Подана», а объект доступен. Она переводит заявку в статус «Одобрена» и сохраняет решение с временем. Арендатор видит решение в карточке заявки.

**Результат** — в хранилище сделок сохранена одобренная заявка со ссылками на арендатора и объект, датами аренды и месячной платой. Решение владельца записано в историю. Одобренная заявка служит основанием для ПР3. Статус объекта остаётся «Доступен» до оформления договора.

## Альтернативы

| Когда | Что делает система |
| --- | --- |
| Шаг 2. Критерии некорректны: минимальная цена больше максимальной, цена или число комнат не больше нуля | Показывает, какие критерии нужно исправить. Поиск не выполняется. |
| Шаг 3. Ничего не найдено | Показывает пустую выдачу и предлагает изменить критерии. |
| Шаг 3. Арендатор переходит на другую страницу выдачи | Показывает следующие 10 карточек с теми же критериями. |
| Шаги 4–5. Объект стал недоступен, пока арендатор смотрел список | Сообщает «Объект недоступен» и обновляет список. |
| Шаг 6. Арендатор записывается на просмотр | Арендатор выбирает дату и время. Система проверяет, что время в будущем и слот объекта свободен. В одной неделимой операции она сохраняет запись «Запланирован» и подтверждает её. Арендатор возвращается в карточку и может подать заявку. Сам просмотр проходит вне ИС. |
| Шаг 6. Время просмотра уже прошло или слот занят | Сообщает причину. Арендатор выбирает другое время. |
| Шаг 6. Арендатор отменяет свою запись на просмотр | Фиксирует отмену и освобождает слот. |
| Шаг 7. У арендатора уже есть активная заявка на этот объект («Подана» или «Одобрена») | Не создаёт вторую заявку и показывает статус существующей. Проверка и создание выполняются как одно действие по паре «арендатор — объект», поэтому два одновременных запроса не создадут дубль. |
| Шаг 7. Объект снят с предложения или уже сдан | Показывает причину отказа. Заявка не создаётся. |
| Шаг 7. Дата начала в прошлом или дата окончания не позже даты начала | Показывает, что нужно исправить. После исправления арендатор отправляет заявку повторно. |
| Шаги 8–10. Пользователь не является владельцем этого объекта | Отказывает в доступе. Заявка не меняется. |
| Шаг 9. Владелец отклоняет заявку | Система проверяет права и статус и переводит заявку в «Отклонена». Решение сохраняется в истории, арендатор видит его в карточке заявки. Он может выбрать другой объект или подать новую заявку на этот же объект, потому что отклонённая заявка не считается активной. |
| До решения владельца. Арендатор отменяет заявку в статусе «Подана» | Заявка получает статус «Отменена». Арендатор может подать новую заявку. |
| Шаг 10. Заявка уже не «Подана» (отменена арендатором или закрыта при снятии объекта) либо объект стал недоступен | Отклоняет решение владельца. Состояния заявки и объекта не меняются. Владелец видит причину. |

## Состояния

| Действие | Заявка | Просмотр | Объект |
| --- | --- | --- | --- |
| Записаться на просмотр | Без изменения | Запланирован | Доступен |
| Отменить просмотр | Без изменения | Отменён | Доступен |
| Подать заявку | Подана | Без изменения | Доступен |
| Одобрить заявку | Одобрена | Без изменения | Доступен |
| Отклонить заявку | Отклонена | Без изменения | Доступен |
| Отменить заявку до решения | Отменена | Без изменения | Доступен |
| Объект снят владельцем (ПР1) | Закрыта | Без изменения | Снят |
| Оформить договор (ПР3) | Оформлена | Без изменения | Сдан |

Активными считаются заявки в статусах «Подана» и «Одобрена». На один объект допускается много заявок от разных арендаторов, а у одного арендатора — одна активная заявка на объект. Одобрение одной заявки не закрывает остальные, объект остаётся доступным до оформления договора в ПР3. Слот просмотра допускает одну действующую запись. Проверка и запись выполняются как одно действие по объекту и времени.

## Доступ и данные

Арендатор работает только со своими просмотрами и заявками. Владелец рассматривает только заявки на свои объекты. Роль и связь пользователя с заявкой проверяются по текущему сеансу при каждой операции. Решения владельца по заявкам сохраняются в истории.

## Граница прецедента

Прецедент заканчивается решением владельца по заявке. Оформление договора по одобренной заявке выполняет агент в ПР3. Уведомления и банковские операции остаются за границей ИС: участники видят результаты в карточках системы.

## Хранилища

**Хранилище недвижимости (`PropertyStorage`)** подбирает карточки доступных объектов по критериям и отдаёт страницу по 10 карточек. **Хранилище сделок (`DealStorage`)** хранит просмотры и заявки, проверяет свободный слот и наличие активной заявки арендатора на объект.
