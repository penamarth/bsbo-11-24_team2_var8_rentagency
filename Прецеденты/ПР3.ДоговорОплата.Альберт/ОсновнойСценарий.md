# ПР3. Оформление договора аренды

**Цель** — оформить аренду по одобренной заявке и исключить повторную сдачу того же объекта.

**Основной исполнитель** — агент. **Участники** — арендатор и владелец жилья. Каждый подтверждает в ИС согласованные условия. Оформление завершает агент.

**Предусловия** — агент вошёл в систему, владелец одобрил заявку арендатора, стороны согласовали условия аренды. При оформлении система проверяет, что заявка одобрена, объект доступен и по нему нет действующего договора.

## Основной сценарий

1. Агент выбирает одобренную заявку и начинает оформление.
2. Система проверяет роль агента по текущему сеансу, статус заявки, отсутствие незавершённого проекта по ней, доступность объекта и наличие действующего договора. Система создаёт черновик с уникальным номером, переносит в него стороны, объект, срок и месячную плату, рассчитывает комиссию и показывает проект агенту.
3. Агент открывает текущую редакцию проекта для подтверждения. Арендатор и владелец могут открыть её в системе.
4. Арендатор и владелец каждый подтверждают условия этой редакции в любом порядке. Система проверяет, что пользователь является соответствующей стороной договора, и сохраняет отдельно для каждой стороны пользователя, редакцию и время подтверждения.
5. После двух подтверждений агент, ведущий этот договор, завершает оформление.
6. Система проверяет оба подтверждения текущей редакции и повторно проверяет заявку и объект. В одной неделимой операции она делает договор действующим, заявку оформленной, а жильё сданным. С этого момента объект закреплён за договором. Агент видит номер и итоговый статус договора.

**Результат** — в хранилище сделок сохранён действующий договор с номером, ссылками на заявку и объект, участниками, агентом, датами начала и окончания, месячной платой, ставкой и суммой комиссии. Этот номер используется в прецеденте расторжения договора.

## Альтернативы

| Когда                                                                                     | Что делает система                                                                                                                                                                         |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Шаг 2. По заявке уже есть незавершённый проект | Если проект ведёт другой агент, система сообщает «Заявка уже в оформлении». Если проект ведёт текущий агент, система открывает этот проект. Проверка и создание нового проекта выполняются как одно действие по заявке. |
| Шаг 2. Заявка не одобрена, объект снят с предложения или уже сдан                         | Показывает причину отказа. Черновик не создаётся.                                                                                                                                          |
| Шаг 2. Не хватает данных или дата окончания не позже даты начала                          | Показывает, что нужно исправить. После исправления агент повторяет создание.                                                                                                               |
| Шаги 3–5. Агент меняет согласованные условия или ставку комиссии                          | Сохраняет новую редакцию, пересчитывает комиссию и возвращает проект в черновик. Старые подтверждения остаются в истории. Агент снова открывает проект для подтверждения обеими сторонами. |
| Шаг 4. Сторона отказывается подтвердить договор                                           | Сторона нажимает «Отклонить условия». Система фиксирует отказ по текущей редакции, блокирует её оформление и показывает решение агенту в карточке договора. Агент может открыть новую редакцию после согласования условий или аннулировать проект.                                                       |
| До завершения оформления. Агент отменяет проект                                           | Договор становится аннулированным. Статусы заявки и объекта при отмене не меняются.                                                                                                        |
| Шаг 6. Другой агент уже оформил аренду этого объекта или заявка перестала быть одобренной | Система отклоняет завершение. Состояния договора, заявки и объекта этот запрос не меняет. Агент может аннулировать проект.                                                                 |

## Состояния

| Действие                                          | Договор                  | Заявка        | Объект        |
| ------------------------------------------------- | ------------------------ | ------------- | ------------- |
| Создать проект                                    | Черновик                 | Одобрена      | Доступен      |
| Открыть проект и подтвердить его обеими сторонами | На подтверждении         | Одобрена      | Доступен      |
| Изменить проект                                   | Черновик, новая редакция | Без изменения | Без изменения |
| Завершить оформление                              | Действует                | Оформлена     | Сдан          |
| Аннулировать проект до завершения                 | Аннулирован              | Без изменения | Без изменения |

По одной заявке допускается один незавершённый проект. По разным заявкам на один объект проекты могут существовать параллельно. Аннулирование освобождает заявку для нового оформления, если она остаётся одобренной и объект доступен. При одновременном завершении двух договоров по одному объекту система принимает только один запрос. Проверка и запись результата выполняются как одно действие по объекту.

## Комиссия и граница прецедента

Комиссия равна месячной плате, умноженной на процент агентства. Например, при плате 40 000 ₽ и ставке 15 % комиссия составляет 6 000 ₽. Ставку и рассчитанную сумму система показывает в проекте и хранит в договоре. Изменение ставки для отдельной сделки требует повторного подтверждения условий. Прецедент заканчивается сохранением действующего договора.

## Хранилища

**Хранилище сделок (`DealStorage`)** хранит заявки, записи о просмотрах и договоры. ПР3 получает оттуда одобренную заявку и сохраняет связанный с ней договор с подтверждениями. **Хранилище недвижимости (`PropertyStorage`)** хранит карточки объектов, опубликованных владельцами, и их статусы. ПР3 читает сведения об объекте и при завершении оформления меняет его статус на «Сдан».
