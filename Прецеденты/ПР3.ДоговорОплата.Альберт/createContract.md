Описания определяются для системных операций (system operations). Системными называются операции, входящие в открытый интерфейс системы для обработки входных системных событий, которые система выполняет как черный ящик. Весь набор системных операций, выполняемых в процессе всех прецедентов, определяет открытый системный интерфейс (system interface), в ракурсе которого система рассматривается как единый компонент или класс. В UML систему в целом можно представить в виде одного класса.

Операция: createContract(applicationID: ApplicationID)

Ссылки: Прецеденты: Оформление договора и оплата

Предусловия: Агент авторизован; заявка с идентификатором applicationID одобрена владельцем (статус APPROVED); объект, указанный в заявке, имеет статус AVAILABLE и у него нет действующего договора

Постусловия:

- Создан экземпляр c класса Contract (создание экземпляра)
- Экземпляр c связан с экземпляром app класса Application на основе соответствия идентификатора applicationID (формирование ассоциации)
- Экземпляр c связан с агентом, оформляющим договор (формирование ассоциации)
- Атрибуту c.number присвоен уникальный номер договора (модификация атрибута)
- Атрибуту c.monthlyRent присвоено значение monthlyPrice объекта Property, указанного в заявке app (модификация атрибута)
- Атрибутам c.startDate и c.endDate присвоены значения из заявки app (модификация атрибута)
- Атрибуту c.status присвоено значение DRAFT (модификация атрибута)
- Атрибуту c.paymentStatus присвоено значение «не оплачен» (модификация атрибута)
- Создан экземпляр cm класса Commission, значение cm.rate определено на основе бизнес-правил расчета комиссии, значение cm.amount рассчитано от c.monthlyRent по ставке cm.rate (создание экземпляра, модификация атрибута)
- Экземпляр cm связан с экземпляром c (формирование ассоциации)
- Экземпляр c вместе с cm сохранен в хранилище сделок (сохранение)
