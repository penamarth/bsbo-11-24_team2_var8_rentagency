Описания определяются для системных операций (system operations). Системными называются операции, входящие в открытый интерфейс системы для обработки входных системных событий, которые система выполняет как черный ящик. Весь набор системных операций, выполняемых в процессе всех прецедентов, определяет открытый системный интерфейс (system interface), в ракурсе которого система рассматривается как единый компонент или класс. В UML систему в целом можно представить в виде одного класса. 


Операция: submitApplication(propertyID: PropertyID, startDate: Date, endDate: Date)

Ссылки: Прецеденты: Подача заявки на аренду 

Предусловия: Арендатор зарегистрирован и авторизован; объект с идентификатором propertyID имеет статус «Опубликован»; у арендатора нет активной заявки на этот объект; дата заселения не в прошлом, срок аренды больше нуля

Постусловия: 
-	Создан экземпляр app класса Application (создание экземпляра)
-	Экземпляр app связан с экземпляром t класса Tenant, подавшим заявку (формирование ассоциации)
-	Экземпляр app связан с экземпляром p класса Property на основе соответствия идентификатора propertyID (формирование ассоциации)
-	Атрибутам app.startDate и app.endDate присвоены значения startDate и endDate (модификация атрибута)
-	Атрибуту app.date присвоено значение текущей даты (модификация атрибута)
-	Атрибуту app.status присвоено значение SUBMITTED (модификация атрибута)
-	Создан экземпляр n класса Notification для владельца объекта p (создание экземпляра)
-	Экземпляр n связан с экземпляром o класса Owner, которому принадлежит объект p (формирование ассоциации)
