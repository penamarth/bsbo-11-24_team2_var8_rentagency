# Бизнес-правила

| Код | Правило | Применение |
|---|---|---|
| ПРАВ1 | Агент проверяет сведения и документы на жильё. Только после одобрения карточка становится доступной в каталоге. При возврате на доработку в карточке сохраняется причина. | ПР1, Property |
| ПРАВ2 | Авторизованный арендатор может подать заявку на доступный объект. Заявку можно подать сразу из карточки объекта без записи на просмотр. У арендатора может быть только одна активная заявка на этот объект. Активные статусы — «Подана» и «Одобрена». | ПР2, Application |
| ПРАВ3 | Комиссия рассчитывается как процент от месячной платы. Агентство задаёт ставку по умолчанию в настройке defaultCommissionRatePercent. Агент может изменить ставку в проекте. Комиссия рассчитывается от платы, согласованной в заявке, с которой началось оформление. Ставка и сумма сохраняются в договоре. | ПР3, Commission |
| ПРАВ4 | Оформление завершает агент, ведущий договор, после подтверждения актуальной редакции арендатором и владельцем и при отсутствии отказа по ней. | ПР3, Contract |
| ПРАВ5 | В каталог попадают только объекты со статусом «Доступен». Просмотры и новые заявки принимаются только по доступным объектам. | ПР2, Property |
| ПРАВ6 | У объекта может быть только один действующий договор. При завершении система неделимо повторяет проверки и сохраняет договор «Действует», заявку «Оформлена» и объект «Сдан». | ПР3, Contract, Application, Property |
| ПРАВ8 | Запись на просмотр возможна на будущее время. На один слот объекта допускается одна действующая запись. При конфликте арендатор выбирает другой слот. | ПР2, Viewing |
| ПРАВ9 | Владелец может снять объект с предложения при отсутствии действующего договора. При снятии активные заявки по объекту закрываются. | ПР1, Property, Application |
| ПРАВ10 | Решение по заявке принимает владелец объекта. При одобрении заявки фиксируется согласованная месячная плата. Для оформления договора нужна одобренная заявка. По одной заявке одновременно возможен один незавершённый проект. Если проект уже ведёт другой агент, начать второй нельзя. | ПР2, ПР3, Application, Contract |
| ПРАВ14 | Подтверждение или отказ фиксируются по стороне и редакции. Изменение условий или ставки создаёт новую редакцию, которую обе стороны подтверждают заново. Отказ блокирует завершение текущей редакции. Ведущий агент может аннулировать проект до оформления. | ПР3, Contract, PartyDecision |
| ПРАВ15 | Запрос на расторжение действующего договора может подать его арендатор или владелец. Агент одобряет или отклоняет запрос. До наступления согласованной даты договор остаётся действующим. В эту дату договор получает статус «Расторгнут», объект — «Доступен». При отказе договор и объект сохраняют текущие статусы. | ПР4, TerminationRequest, Contract, Property |
| ПРАВ16 | Каталог по умолчанию показывает 10 самых популярных доступных объектов на первой странице. Поиск по критериям сохраняет постраничный вывод по 10 карточек. | ПР2, SearchCriteria, PropertyCard |
| ПРАВ17 | Владелец работает со своими объектами и заявками на них, арендатор — со своими просмотрами и заявками. Агент проверяет объекты, оформляет и расторгает договоры. Действия сторон проверяются по конкретной сделке. | ПР1–ПР4, User |
| ПРАВ18 | Доступ к персональным данным и документам предоставляется по роли и связи пользователя с записью. | ПР1–ПР4, User, PropertyDocument |

Номера действующих правил сохранены для ссылок из сценариев. Правила прежней интеграции с оплатой исключены из общей модели.
